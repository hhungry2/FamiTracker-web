# 市販ゲームのNSFドライバー読み込み

日本語 | [English](NSF_game_drivers.en.md)

更新: 2026-10-10。[Issue #21](https://github.com/hhungry2/FamiTracker-web/issues/21) の最初の対応として、公開された解析資料があるカプコンのロックマン1・2を追加した。

## 対応範囲

| 作品 | 確認したプログラム | 対象 |
| --- | --- | --- |
| ロックマン1 / Mega Man | 米国版の標準音源ドライバー、$8000配置 | BGM 16曲 |
| ロックマン2 / Mega Man II | 米国版の標準音源ドライバー、$8000配置 | BGM 24曲 |

作品名だけでは識別しない。公開ソースから組み立てたドライバー全体について、長さと異なる2種類の32bitフィンガープリントを照合する。周波数テーブルも照合範囲に含む。ゲームの地域名ではなくこの一致条件で判定するため、別地域版・改造版・別リッピング方式まで対応すると保証するものではない。

資料は [Bisqwitの解析](https://www.bisqwit.iki.fi/jutut/megamansource/)、[Mega Man 1の逆アセンブル](https://github.com/lsmmega/mm1/tree/b606a84840aea70f1298ddd9cf832bda69d99d27)、[Mega Man 2の逆アセンブル](https://github.com/lsmmega/mm2/tree/8e378590488ce589c526f0d24ad4dee60afd14a3)。後二者は米国版のROM識別値をREADMEに記載している。

NSF・NSFe・NSF2の共通コンテナーと初期バンクを読み取る。ゲーム用には、Dn-FT固有の「play = init + 3」やパターンバンクの規則を適用しない。標準ドライバーのplay入口、そこへのJMP、JSRとRTSによる単純なラッパーに対応する。

NSFの曲番号とゲーム内部の曲番号は一致するとは限らない。初期化ラッパーのRAMクリア、曲番号の加減算、曲番号テーブル、基本的な分岐・サブルーチンを制限付きで解釈し、$8003への呼び出しに渡される番号を取得する。未対応の命令、バンク変更、速度・フェード・ポーズの外部操作などはフォールバックの理由になる。

## 読み取りの流れ

1. ドライバーのコードを識別し、初期化ラッパーから曲番号を得る。
2. BGMヘッダーと4チャンネルのポインターを読む。
3. 音符、休符、音長、テンポ、付点、三連符、タイ、有限・無限ループを解読する。音量・デューティー・ピッチ・モジュレーターの各コマンドも検査する。
4. 各チャンネルを独立した1/4フレーム単位の時計で進め、全チャンネルが同じ曲状態へ戻る位置を求める。
5. 求めた長さに応じてNSFPlayを動かし、APUの実際の音色状態を採取する。解読したループと実際のチャンネル状態が一致することも確認する。最初の周回で音色が安定しない場合は、その周回をイントロへ含める。
6. 共通の楽譜変換処理に確定した終端・ループ位置を渡し、自動再構築する。シーケンス化・行圧縮の結果は変換直後の楽譜とのPCM比較を通った場合だけ採用する。

**ゲーム用の読み取りは、曲構造の直接解読と演奏解析を組み合わせる方式である。** 三角波の長さカウンターや音量エンベロープなどのAPU動作を、独自の簡易エミュレーターで置き換えてはいない。Dn-FT方式のように全音色資源を直接復元する方式とは区別する。

原作者のパターン区切り、拍子、小節、音色名、未使用データは復元しない。再構築後の行には異なる長さのFxxが設定されるため、固定した拍・小節の強調を無効にする。

## 全曲とフォールバック

通常のNSF読み込みで「ドライバ別解読」を選ぶ。全曲がデフォルトで、1曲1トラック、先頭64曲までを1つのモジュールに格納する。単曲選択にも対応する。分割保存・ZIP保存は追加しない。

BGMと効果音が混在する場合、BGMを解読し、効果音だけを既存の演奏解析へ切り替える。未対応の初期化命令、壊れたポインター、未知のコマンド、処理上限、実際の演奏と一致しないループも曲ごとに切り替える。画面で該当する曲番号を通知し、保存モジュールのコメントに理由を残す。ドライバー自体が識別できない場合は従来どおりファイル全体を演奏解析する。

解読できたBGMでは解析時間・行数の設定を曲の終端判断に使わない。フォールバックした曲では通常の演奏解析設定を使う。バッチで増える音色が容量を圧迫する場合、後続曲はPCMで検証した行圧縮を優先する。曲によっては圧縮できず、元の行数を保持する。

解読は最大65,535フレーム、200万コマンド、同一時刻の4,096コマンド、初期化は10万命令・16段のサブルーチンまで。上限到達時に不完全な解読結果を採用しない。キャンセル・失敗時は編集中のモジュールを保持する。

## 検証

公開ソースの音楽データをローカルで組み立てたBGM集を使い、曲全体の解読、ループの演奏照合、バッチ取り込みを確認した。ゲームの音楽データとバイナリーはリポジトリへ追加していない。

| 検証対象 | 曲数 | 変換直後の総行数 | 再構築後の総行数 |
| --- | ---: | ---: | ---: |
| Mega Man 1 米国版BGM | 16/16 | 26,236 | 17,230 |
| Mega Man 2 米国版BGM | 24/24 | 50,682 | 34,118 |

37曲は変更後のPCM比較が一致し、3曲は圧縮効果がなく元の楽譜を採用した。この結果は同じコードの全リッピング版への対応保証ではない。

CIでは、固定コミットの公開ソースから**音源ドライバーだけ**を組み立て、新しく作ったテスト用音符を付ける。ゲームの曲やROMをテスト資材として配布しない。

```sh
node web/test/build-capcom-reference.mjs  # ca65/ld65とネットワークが必要
node web/test/nsf-capcom.mjs
```

両ドライバーで、曲番号の並べ替え、4チャンネル、テンポ・付点・三連符・タイ・繰り返し、NSF/NSFe/NSF2・初期バンク、効果音のフォールバック、64トラック、破損・無限ループ・キャンセル、シーケンスの共有と保存・再読み込みを検証する。バッチと単曲のPCMはループ境界を越えて比較する。

テスト音符の原NSFと変換結果の5秒間のスペクトル類似度は、両作品ともパルス1が0.991、パルス2が0.993、三角波が0.981、ノイズが0.797～0.799だった。開始のずれは0.1秒未満を確認する。これは元NSFとのサンプル単位の一致ではなく、音源エミュレーター・位相・更新時刻が異なる場合の音の近さの検証である。自動再構築のPCM完全一致は、あくまで変換後の楽譜を基準とする。

## 今後の範囲

効果音の直接解読、音色コマンドを全て直接シーケンスへ変換する方式、変更された音源コード、動的バンク切り替え、他作品・別エンジンのプロファイルは今後の対象とする。[Issue #21](https://github.com/hhungry2/FamiTracker-web/issues/21) は継続する。
