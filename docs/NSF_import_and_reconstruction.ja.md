# NSFの読み取りと再構築

[English](NSF_import_and_reconstruction.en.md) | 日本語

更新日: 2026-10-09。対象はFamiTracker-webのブラウザ版です。

NSF／NSFeを編集可能なトラッカーデータへ変換する読み込み機能と、読み込み後のデータを整理する再構築機能は、**このWeb版で独自に追加した機能**です。元のDn-FamiTrackerのNSF書き出しとは別の処理です。

## 最初に試す手順

1. [GitHub Pagesのエディタ](https://hhungry2.github.io/FamiTracker-web/editor.html?lang=ja)または[zxtune.comのエディタ](https://zxtune.com/ja/create/famitracker)を開きます。
2. 「開く」、「読み込み → NSF から開く…」、またはファイルのドロップで `.nsf`／`.nsfe` を選びます。
3. 読み取り方式を選びます。最初は「演奏解析」、対応するDn-FT 2.16のファイルなら「ドライバ別解読」も試せます。
4. 「曲」は初期状態で全曲です。必要なら1曲を選び、読み込みます。
5. 演奏解析で取り込んだトラックを選び、「曲 → NSF 読み込みを再構築」を実行します。
6. 元のトラックと追加された再構築トラックを確認し、通常の「保存」で1つの `.dnm` ファイルに保存します。

NSF読み込みは新しいモジュールを開きます。編集中の曲がある場合は、先に保存してください。再構築は現在のモジュールへ別トラックを追加します。

## 2つの読み取り方式と再構築

| 項目 | 演奏解析 | ドライバ別解読 | 読み込み後の再構築 |
| --- | --- | --- | --- |
| 入力 | NSF／NSFeの演奏結果 | 対応ドライバが持つ楽曲データ | 演奏解析で作ったspeed 1のトラック |
| 処理 | NSFPlayで演奏し、音源チップの状態を記録 | ドライバ本体を照合し、行・ノート・命令などを解読 | 音量・音程変化を推定シーケンスへ移し、変化のない行をまとめる |
| 行の意味 | 音源の1フレームが1行。標準NTSCでは約60行／秒 | 書き出されたパターンの行 | Fxxで長さが決まる行。行ごとの時間は一定とは限らない |
| 読みやすさ | 細かな音量・音程変化が多くの行に展開される | 解読できた範囲で元の入力に近い構造が得られる | 入力欄と行数を減らせる。拍や小節は推定しない |
| 対応範囲 | NSFPlayと変換処理が扱える形式・音源 | このリポジトリのDn-FT 2.16ドライバと対応データ | 対応する形式を保った演奏解析トラック |
| 失敗時 | エラーを表示し、編集中のモジュールを保持 | 解読できない場合は演奏解析へ切り替え、その旨を表示 | 検証できなければ適用せず、元のデータを保持 |

NSFは再生プログラムと楽曲データの形式です。一般に、作曲時のプロジェクトを丸ごと含んでいるわけではありません。どの方式も元の入力・音色名・未使用データなどの完全復元を保証しません。表示はトラッカーの縦型パターンで、五線譜やピアノロールへ変換する機能ではありません。

## 演奏解析の設定

| 設定 | 動作と選び方 |
| --- | --- |
| 曲 | 「全曲」は先頭から最大64曲を1曲1トラックで読み込みます。1曲を個別に選ぶこともでき、65曲目以降も個別選択できます。 |
| 地域 | 両方式に対応するファイルではNTSC／PALを選択します。直接解読でも指定した地域を使用します。 |
| 調べる長さ | 各曲を解析する上限です。通常は5分。NSFeの曲長があれば、2周以上を調べられる長さへ調整します。画面の上限は18分です。ループ検出には繰り返しを十分に演奏する必要があります。 |
| パターンの行数 | 64／128／256行ごとの区切りです。曲全体の行数は減りません。必要なフレーム数が多いと、自動で長いパターンを使います。 |
| 繰り返しを見つけてループにする | 演奏の反復を検出してBxxで戻ります。検出できない曲や無音になる曲はC00で停止します。 |
| 最初の無音を省く | 先頭の無音を取り除きます。 |

全曲読み込みでは、同じ内容の音色・DPCMサンプルを共有します。64音色、64サンプル、サンプル総容量256 KB、または曲間の再生設定の違いによって一緒に収録できない場合、その曲の前で止め、取り込めた曲数と理由を表示します。解析範囲が無音の曲も、警告付きの停止トラックとして残します。分割保存やZIP保存はなく、結果を通常の保存で1つのモジュールとして保存します。

演奏解析から作った音は、NSFの直接再生と必ず波形が一致するわけではありません。元の演奏の再現性と、後述する再構築前後の一致は別の検証です。

## ドライバ別解読の対応範囲

現在は、このリポジトリの書き出しに使う **Dn-FT 2.16** のドライバ本体を照合します。この番号はドライバの識別バージョンで、アプリのバージョン番号ではありません。NSF／NSFe／NSF2の対応データから、パターン、演奏順、速度・テンポ、対応エフェクト、シーケンス、波形、VRC7パッチ、DPCM割り当てなどを読み取ります。音源は2A03、VRC6、VRC7、FDS、MMC5、N163、S5Bと複数音源構成です。画面で開けるファイル拡張子は `.nsf`／`.nsfe` です。

直接解読では、演奏解析用の長さ・パターン行数・ループ検出・無音除去の設定を使いません。書き出された構造を読み取ります。全曲の初期選択と64トラック上限は共通です。

未知のドライバ、別バージョン、改造コード、不整合な圧縮ストリーム、未対応データなどは演奏解析へ切り替わります。**市販ゲームの独自ドライバを直接解読する機能は、まだ実装していません。** 演奏解析はドライバの識別を必要としませんが、任意のゲームの完全な再現を保証するものではありません。

現状、付属デモ5曲の書き出しは1曲が直接解読でき、4曲は圧縮ストリームの整合性検査で演奏解析へ切り替わります。詳しくは[ドライバ解読の対応範囲と検証](NSF_driver_decoding.md)と[Issue #14](https://github.com/hhungry2/FamiTracker-web/issues/14)を参照してください。

## 再構築が行うこと

選択したトラックを対象に、次の処理を試します。

1. 対応する発音区間の音量・Pxxによる音程補正を、新しい音色のシーケンスへ移します。
2. 同じシーケンス・音色・パターンを共有します。
3. 変化のない区間をまとめ、残した行の長さをFxxで調整します。
4. 再構築前後を別エンジンで再生して検証し、一致した候補だけを別トラックとして追加します。

元のトラック・音色・サンプルを残すため、64トラックのうち少なくとも1枠の空きが必要です。未編集の演奏解析結果を `.dnm` へ保存し、開き直した場合にも実行できます。全曲を一括処理する機能ではなく、選択した1トラックに適用します。

| 音源 | 音量シーケンスの推定 | Pxxの音程シーケンスの推定 |
| --- | --- | --- |
| 2A03パルス | 対応 | 対応 |
| 2A03三角波 | 元の入力を保持 | 対応 |
| 2A03ノイズ | 対応 | 元の入力を保持 |
| MMC5・VRC6・S5B | 対応 | 対応 |
| N163 | 対応 | 元の入力を保持 |
| DPCM・FDS・VRC7 | 元の入力を保持 | 元の入力を保持 |

シーケンス化しない部分も、可能なら行の整理を適用します。既存シーケンス付き音色、&&による継続音、リリース、発音途中の音色変更、ループ境界を跨ぐ音、252項目を超えるシーケンス、空き枠不足などでは、該当する入力を残します。音程の推定は周期ベースに限り、リニアピッチ、ハードウェアスイープ、位相リセットなどは対象外です。

速度・グルーヴ・未対応エフェクト・複雑な分岐などを追加したトラックは対象外です。シーケンス化も行の整理もできない場合、新しいトラックは追加しません。再構築後は1行の時間が一定ではないため、固定の拍・小節の強調を無効にし、先頭ブックマークで保存後の表示にも適用します。行数を減らしても、作曲者の拍子・元の入力行・元の音色構造を特定したことにはなりません。

## 再構築前後の音の検証

元トラックと候補を、それぞれ独立したエンジンで44.1 kHzのPCMに変換し、サンプル単位で比較します。全体ミックスと、シーケンス化した各チャンネルを比較します。範囲はイントロ＋ループ2周＋境界処理用1秒で、停止する曲は取り込んだ曲長に境界処理分を加えます。

音量＋音程の候補が一致しない場合は「音量のみ」、次に「空行整理のみ」を試します。どれも一致しない場合は適用しません。**比較相手は演奏解析で取り込んだ元トラックで、NSFの直接再生や作曲時の入力ではありません。**

処理はキャンセルできます。失敗・キャンセル、または処理中の編集・ファイル差し替えを検出した場合、元のデータや新しい編集内容を保持します。進捗が100%に達するまで時間がかかる場合も、適用前の比較が含まれます。

## 確認済みの例と保存

付属デモ5曲をそれぞれNSFへ書き出し、先頭約20秒（1,200フレーム）を演奏解析して再構築した結果です。全曲で保存・再読み込み後のPCM一致を確認しています。この結果は任意のファイルで同じ削減率になることを示すものではありません。

| デモ | 読み込み直後の行数 | 再構築後の行数 |
| --- | ---: | ---: |
| Trapped Within a Memory | 1,200 | 1,001 |
| Hellpath | 1,200 | 887 |
| The Wavetable That Doesn't Wanna Be | 1,200 | 928 |
| GOAted Ambition | 1,200 | 846 |
| Hell or High Water | 1,200 | 643 |
| 合計 | 6,000 | 4,305 |

保存した `.dnm` には元トラックと再構築トラック、追加音色が含まれます。自動保存とは別に、通常の保存でファイルを手元に保存してください。

## インターフェイスの言語

エディタ全体は日本語、英語、簡体字中国語、繁体字中国語、韓国語、スペイン語、ブラジルポルトガル語、フランス語、ドイツ語、ロシア語に対応します。GitHub Pagesでは `editor.html?lang=ja` のように指定でき、指定がなければブラウザの言語を使います。zxtune.comではサイトの言語選択がエディタにも適用されます。音名・エフェクト記号・ファイル内の曲名などは言語選択で変更しません。
