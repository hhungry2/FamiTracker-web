# NSF読み込み方式の比較

調査日: 2026-10-05 / 更新: 2026-10-09

対象: Web版Dn-FamiTrackerのNSF／NSFe読み込み

現在の方式は、NSFを演奏して音源チップの状態からトラッカーのデータを作る方式です。ドライバ別解読は、NSF内部に残っている楽曲データを直接読み取り、元の入力に近いトラッカーのデータを作る方式です。

**ドライバ別解読を別の読み取り方式として実装しました。対応するDn-FT 2.16を直接解読し、未対応・不整合なデータは演奏解析へ切り替えます。全曲が初期選択、上限は64トラックです。[対応範囲・制限・検証](NSF_driver_decoding.md)を参照してください。**

## 比較表

| 比較項目 | 現在の方式: 演奏結果から変換 | ドライバ別解読: 楽曲データを直接変換 |
| --- | --- | --- |
| 実装状況 | 実装済み。NSFPlayで演奏してフレームごとの状態を記録する | 初期実装済み。Dn-FT 2.16の本体を照合して直接解読。未知の版や不整合な圧縮ストリームは演奏解析へ切り替える |
| 読み取る情報 | 各チャンネルの音程、音量、音色、発音・停止などの状態とイベント | ドライバ固有形式のノート、継続時間、演奏順序、速度、音色、エフェクトなど |
| 対応範囲 | 作成ドライバを特定せずに読み込める。ただしNSFPlayと変換処理が扱える形式・音源の範囲に限る | 対応したドライバとバージョンに限る。独自改造や異なるデータ配置にも対応が必要 |
| ノートの作り方 | 実際の周期・周波数に近い音名を選び、Pxxで音程を補正する。発音位置はチップの状態と書き込みから判定する | 内部のノート命令を読み取れるため、鳴った音程から逆算するより元の入力に近づけられる |
| 1行の単位 | NSFの1フレームを1行にする。通常のNTSC設定では約60行／秒 | 元のパターン行や、ドライバが持つ時間単位を利用できる。FamiTracker系では速度と継続時間を解読して元に近い行間隔を復元することが目標 |
| 曲全体の行数 | 20秒を読み込むと約1,200行になる | 元が複数フレームで1行を進める入力なら、行数を減らせる可能性がある。元がspeed 1などの場合は行数が減るとは限らない |
| 音量の変化 | 変化するフレームごとに音量列へ記録する | 音量シーケンスや音量命令として保存されていれば、その構造を復元できる |
| ビブラート・アルペジオなど | 結果の音程変化がPxxや、継続中の音程変更を示すノートと&&に展開されることがある | シーケンスやエフェクト命令を解読できれば、少ない入力で表現できる。個々の変化が元からノートで入力されている場合は、そのノートを残す |
| インストゥルメント | 原則としてシーケンスを持たず、チップ・波形・パッチ・サンプルなどから作る | 保存されている波形、サンプル割り当て、シーケンスなどを解読し、元に近い音色構造へ戻せる可能性がある |
| スピード・テンポ | speed 1。通常はNTSCでtempo 150、PALで125。独自の演奏レートではtempo 0とエンジン速度を使う。元の入力のスピード・テンポを復元しているわけではない | 初期設定や途中の速度変更命令を解読できれば、元の演奏タイミングを復元できる |
| 拍・小節の読みやすさ | 行強調は既定の4行／16行。曲の拍に合わせた復元・調整は行わない | 元に近い行間隔が得られるため、拍を追いやすくなる可能性がある。ただし拍子や行強調の設定が保存されていなければ、推定や手動調整が必要 |
| パターン・ループ | 演奏した範囲の反復を検出し、Bxxなどでループを作る。同じ行内容のパターンを共有する | 演奏順序や分岐命令を解読できれば、曲の構造を直接読み取れる。ただし書き出し時に統合された元のパターン番号などは復元できない場合がある |
| トラッカーの読みやすさ | 細かな音の変化が行や列に並び、入力ノートと音色の動きを区別しにくい | 入力ノートと音色の動きを分けられるため、元の入力に近い読みやすさが期待できる |
| 再生音の一致 | デモ曲・各音源などを使った既存テストは通過。検証は主に短時間スペクトルの類似度であり、波形の完全一致を保証するものではない | 検証用モジュールで各音源のPCMを元のモジュールと比較。2A03はNSF直接再生・演奏解析とのチャンネル別比較も実施。全ての曲の一致は保証しない |
| 元の編集内容の完全復元 | 保証できない | 保証できない。書き出しで省略・統合・変換された情報は、ドライバを解読しても戻せない場合がある |
| 実装・保守の負担 | 共通の解析・変換処理を音源ごとに保守する | ドライバとバージョンごとの識別・解読・検証が必要。まずDn-FamiTracker製NSFから対応するのが現実的 |

## 現在の方式で確認した例

リポジトリのデモ5曲をNSFへ書き出し、それぞれ先頭20秒を解析して読み込み直しました。ループ検出は無効にしています。5曲とも読み込み結果は1,200行でした。

| デモ曲 | 全体の行数 | ノート・音切り・リリースがある行 | それらがなく、音量・音色指定・エフェクトなどだけがある行 | 完全な空行 |
| --- | ---: | ---: | ---: | ---: |
| Trapped Within a Memory | 1,200 | 537 | 467 | 196 |
| Hellpath | 1,200 | 402 | 596 | 202 |

集計は全チャンネルを合わせた行単位です。&&を伴う継続中の音程変更も「ノートがある行」に含むため、新しく音を鳴らした回数を示す表ではありません。

直接解読の検証用モジュールは元の32行・3フレームを復元しました。付属デモ1曲を直接解読し、4曲はストリームの整合性検査で演奏解析へ切り替えることを確認しています。詳細は[実装の検証](NSF_driver_decoding.md#検証)を参照してください。

## 行数を減らす方法との違い

| 方法 | 楽曲データへの作用 | 再生音への作用 |
| --- | --- | --- |
| コンパクト表示 | 表示する列と横幅を減らす。縦の行数は変わらない | 表示だけなので変わらない |
| 行の折り畳み表示を追加 | 内部の行を保持し、複数行をまとめて表示する。現在は未実装 | 表示だけなので変わらない |
| NSF読み込み時の「パターンの行数」を変更 | 曲を64／128／256行ごとに区切る。曲全体の行数は減らない | 同じ演奏内容を別の区切りで保持する |
| 「曲 → NSF 読み込みを再構築」 | 音量・Pxxの変化を推定シーケンスへ移し、変化のない行をまとめた別トラックを追加する。元のトラック・音色は保持する | 適用前に元トラックと再生音を比較し、一致した結果を採用。推定が一致しなければ音量のみ、空行整理のみへ順に切り替える |
| 既存の「パターン → 縮小」 | 選択範囲のデータを1行おきに残して詰め、後半を空にする。パターンの行数設定は変わらない | 間引かれた音符や変化が失われ、タイミングも変わり得る |
| ドライバ別解読を追加 | ノート・時間・シーケンスなどを解読し、別の行構成で楽曲データを作る | 対応するデータの行数・速度・シーケンスを復元する。検証用モジュールで保存後のPCM一致を確認。未対応時は演奏解析を使う |

読みやすいトラッカーのデータを得ることが目的なら、対応ドライバには直接解読を使い、未対応のドライバには現在の方式を使う構成が候補になります。表示だけを改善する折り畳みや継続線も、それぞれの読み込み結果に併用できます。

## 演奏解析からの再構築

「曲 → NSF 読み込みを再構築」で、選択したトラックの音量・音程変化を音色シーケンスへ移し、空行をまとめた別トラックを追加します。元のトラック・音色・サンプルは保持し、必要な音色だけ複製します。同じ内容のシーケンスと音色は共有し、残した各行の時間を Fxx で調整します。NSFを演奏解析で読み込んで保存した `.dnm` を開き直した場合も、元の speed 1 のトラックなら対象にできます。上限64トラックのうち、追加用に1枠の空きが必要です。

これは演奏結果の整理であり、元の入力ノートや拍・小節の完全復元ではありません。編集で速度・グルーヴ・対応外のエフェクトや分岐を追加した場合は処理を中止します。シーケンス化も空行整理もできない場合はトラックを追加しません。再構築後の行は時間の長さが異なるため、固定間隔の行強調は無効にしています。先頭のブックマークで強調なしを持続させ、保存・再読み込み後の表示にも適用します。既存のファイル形式ではトラックごとの基準値を保存しないため、再読み込み後にツールバーの基準値だけ4／16へ戻る場合がありますが、ブックマークが描画の強調を無効にします。

| デモ曲 | 読み込み直後 | 空行整理のみ | 今回の再構築 | 追加音色／シーケンス |
| --- | ---: | ---: | ---: | ---: |
| Trapped Within a Memory | 1,200 | 1,004 | 1,001 | 3／3 |
| Hellpath | 1,200 | 998 | 887 | 19／19 |
| The Wavetable That Doesn't Wanna Be | 1,200 | 928 | 928 | 2／2 |
| GOAted Ambition | 1,200 | 1,074 | 846 | 14／16 |
| Hell or High Water | 1,200 | 680 | 643 | 9／9 |
| **合計** | **6,000** | **4,684** | **4,305** | **47／49** |

比較条件は各デモをNSFへ書き出し、先頭1,200フレーム（約20秒）を従来方式で解析したものです。この範囲ではループは検出されず、元の比較と同じ1,200行でした。5曲すべてでフォールバックせずに採用され、保存・再読み込み後も20秒全体のPCMサンプルが一致しました。空行整理だけの場合から、合計でさらに379行減っています。The Wavetable…は他チャンネルのイベントが行を占めるため、シーケンス化しても曲全体の行数は同じです。

### 適用前の自動検証

候補は編集用とは別のエンジン上で作り、44.1 kHzのPCMをサンプル単位で比較します。全体のミックスに加え、シーケンス化した各チャンネルの単独再生も比較します。検証範囲はイントロ＋ループ2周に境界処理用の1秒を加えた長さです。停止する曲では取り込んだ曲の長さを検証します。NSFの取り込み前の音ではなく、**従来方式で取り込まれた元トラックとの一致**を確認する処理です。

音量＋音程の候補が一致しなければ、音量のみ、次に空行整理のみを試します。いずれも一致しない場合は変更を反映しません。キャンセルに対応し、処理中に元データが編集・差し替えされた場合もそのデータを優先して候補を破棄します。保存状態のフラグとチャンネルのミュート状態も保持します。

### シーケンス化の対象と制限

| 対象 | 音量 | Pxxによる音程補正 |
| --- | --- | --- |
| 2A03 パルス | 対応 | 対応 |
| 2A03 三角波 | 元の音量列を保持 | 対応 |
| 2A03 ノイズ | 対応 | 元のPxxを保持 |
| MMC5・VRC6・S5B | 対応 | 対応 |
| N163 | 対応 | 元のPxxを保持 |
| DPCM・FDS・VRC7 | 元の入力を保持し、空行整理を適用 | 元の入力を保持し、空行整理を適用 |

音色番号のある通常の発音から、次の通常発音または音切りまでを対象にします。既存の有効なシーケンスがある音色、&&を伴う継続音、リリース、途中の音色変更、ループ境界を跨ぐ音は元の入力を保持します。末尾の同値をまとめても252項目を超える変化、音色・シーケンスの空き枠がない場合も該当部分を残します。音程は周期ベースに限定し、リニアピッチ、範囲外のPxx、ハードウェアスイープ、位相リセットを含む区間では元のPxxを保持します。

テストではこれらの条件、イントロとループ境界、各音源の複数周ループ、元トラック・音色の保持、保存・再読み込み、枠不足、64トラック上限、故意に注入したPCM不一致、途中編集とキャンセルを確認しています。任意のNSFで元の編集内容を完全復元するものではありません。

ドライバ別の解読は別方式として実装済みで、拡張は [GitHub Issue #14](https://github.com/hhungry2/FamiTracker-web/issues/14) で追跡しています。
